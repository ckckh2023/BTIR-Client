# BTIR-Client
BTIR 项目的客户端版本，可与服务端对齐，为网页版使用扩展更多场景。

服务端相关内容在 https://github.com/ckckh2023/BTIR-BrainTumor-ImageRecognition

## 鸿蒙模拟器

在这台 Linux 开发机上运行 `btir-phone start` 可启动模拟器、BTIR 应用和本机上传转发服务；用 `btir-phone status` 检查状态，`btir-phone stop` 停止。真机无需本机转发服务。

模拟器上传使用 `10.0.2.2` 将数据交给只监听电脑本地地址的转发服务，电脑再通过 HTTPS 发送到正式服务端。由于模拟器原生 multipart 上传会破坏文件末尾，应用将文件按 1 MiB 分块发送，由转发服务流式组装表单。转发服务最多缓存 4 MiB 分块，不保存病例文件；日志只记录上传路径、字节数和 HTTP 状态码。

ZIP 和四模态 NIfTI 上传共用这条转发流程。四模态上传须分别选择 FLAIR、T1CE、T1、T2 文件。

## 病例管理与报告

在“病例列表”中，同一病例的检查按病例 ID 归在一组；组内显示的是当前分页中的检查次数。“新增复查”位于病例标题，检查卡片默认只显示详情和管理入口，重命名、归档、恢复及彻底删除可在“管理”中操作。列表可以切换“病例检查”和“已归档”，状态筛选按需展开。已结束的任务可归档；归档任务可恢复，也可在确认后彻底删除。彻底删除无法恢复，归档列表显示服务端计划的自动清除时间。

已完成或部分完成的任务，在详情页点击“预览并导出报告 PDF”，再点击“保存 PDF”选择存储位置。PDF 在设备本地生成，包含当前可用的分析结论与影像预览。

病例列表中的“新增复查”会打开上传页并带入同一病例 ID；也可以从任务详情的“随访对比”卡片进入。上传并完成分析后，详情页可选择任一已完成的历史检查作为基线，查看体积、面积与分类概率的变化。病例列表中的“重命名”调用服务端接口，任务名与同病例的病例名会同步更新。
